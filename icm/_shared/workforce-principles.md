# Agent Workforce Principles

Derived from the supplied AI-workforce transcript and adapted to Grant Agent.

## 1. The human should decide, not micromanage
The mature operating model is escalation-based. Humans define goals, risk boundaries, and approvals; the agent workforce chooses routine execution paths within them.

## 2. "Do smart things" is earned autonomy
The orchestrator should periodically inspect goals, deadlines, new evidence, connected-system changes, and pipeline friction and propose or perform useful work within its permission tier. A vague proactive mandate is safe only because goals, context, and risk boundaries are explicit.

## 3. Expand breadth without expanding risk
More initiative does not mean more authority. The agent may discover more grants, prepare more drafts, or identify more problems while the submission/send/spend threshold remains unchanged.

## 4. Make the organization queryable
Email, meeting notes, Drive/Dropbox, Slack/Teams, calendars, CRM, budgets, legal documents, past proposals, and human observations should resolve into one queryable organizational context. ICM is canonical; connected systems and indexes feed it with provenance.

## 5. Multiplayer by default
Humans and agents share the same work. Team members can ask the Grant Director in chat or an approved team channel. The agent answers from permissions-aware shared context rather than one person's private session history.

## 6. Watch the workforce
A dedicated Watchdog observes repeated corrections, duplicated work, stale facts, blocked permissions, missing context, deadline risk, and unnecessary human handoffs. Its job is to make the system easier to work with over time.

## 7. Build the factory, then instances
Do not handcraft every nonprofit. Build onboarding templates, source adapters, roles, evaluation suites, connector policies, and grant records once. Each customer is an instance generated from the factory.

## 8. Use the smallest capable worker
The orchestrator delegates bounded work to smaller/cheaper models or deterministic code where possible. Expensive reasoning is reserved for strategy, ambiguous eligibility, final synthesis, and critique.

## 9. Proactive undefined work needs a North Star
Every organization ICM has current goals, funding priorities, program constraints, and "do not" rules. The agent can roam only inside that goal/permission envelope.

## 10. Context corrections become system improvements
When a user repeatedly corrects an output, the response is not merely to retry. Determine whether context, routing, source freshness, a skill, or a permission boundary is missing and propose a durable fix.
